# Learning to Code: Teaching Rationale

The optional [Learning to Code](../../markdown/learning_to_code.md) guide supports independent understanding alongside the use of browser chat and coding assistants. Its routine is to predict, try a small step, request focused help, check the result and revisit the idea later.

The design draws on [PRIMM's approach to reading and modifying programs](https://suesentance.net/2019/05/06/new-paper-primm-and-sociocultural-theory/) and research on [retrieval practice and spaced study](https://doi.org/10.1177/1529100612453266). These are foundations for the suggested activities, not evidence that this particular guide improves learning.

AI-supported task completion and independent understanding should be checked separately. A [university programming study](https://doi.org/10.1016/j.caeai.2025.100537) found better exercise performance without additional demonstrated knowledge gains. A [physics tutoring experiment](https://doi.org/10.1038/s41598-025-97652-6) found positive immediate learning effects with a specifically designed tutor. Different tasks, learners and forms of support limit direct comparisons and transfer to this course.

The guide therefore asks students to explain code, trace another case and check claims against actual sources or measurements. Its worked examples use the repository's IR conversion, Workshop 3 state selection and Workshop 5 data format. Calculations and isolated code checks do not establish physical controller behaviour. No student evaluation of the guide has been conducted.

Prepared with AI assistance; reviewed against the linked repository examples on 21 October 2026. Detailed research and review materials for the CAS are maintained separately. The guide introduces no new assessment requirements and does not define which AI tools are permitted in assessed work.
