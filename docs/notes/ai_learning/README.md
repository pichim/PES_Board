# Learning to Code with AI: Teaching Rationale

The optional [Learning to Code with AI](../../markdown/learning_to_code.md) guide supports independent understanding alongside the use of browser chat and coding assistants. Its routine is to predict, try a small step, request focused help, check the result and revisit the idea later.

The design draws on [PRIMM's approach to reading and modifying programs](https://suesentance.net/2019/05/06/new-paper-primm-and-sociocultural-theory/) and research on [retrieval practice and spaced study](https://doi.org/10.1177/1529100612453266). These are foundations for the suggested activities, not evidence that this particular guide improves learning.

AI-supported task completion and independent understanding should be checked separately. A [university programming study](https://doi.org/10.1016/j.caeai.2025.100537) found better exercise performance without additional demonstrated knowledge gains. A [physics tutoring experiment](https://doi.org/10.1038/s41598-025-97652-6) found positive immediate learning effects with a specifically designed tutor. Different tasks, learners and forms of support limit direct comparisons and transfer to this course.

On 28 October 2026, [Bauer et al.'s ISAR model](https://doi.org/10.1007/s10648-025-10020-8) was added as a retrospective conceptual lens. It distinguishes inversion (reduced cognitive engagement and learning), substitution (instructional equivalence), augmentation (additional cognitive support within the task) and redefinition (a task change that supports deeper processing than the comparison condition). The guide aims to preserve students' reasoning while providing focused help. Whether an interaction achieves augmentation or redefinition depends on its design and comparison condition; a chat interface alone establishes neither. These are design intentions, not measured effects in this course.

The guide therefore asks students to explain code, trace another case and check claims against actual sources or measurements. Its worked examples use the repository's IR conversion (Workshop 1), distance-to-servo mapping (Workshop 2) and state selection (Workshop 3). Calculations and isolated code checks do not establish physical controller behaviour. No student evaluation of the guide has been conducted.

For ZHAW assessed work, the [ZHAW Assessment Guideline](https://gpmpublic.zhaw.ch/GPMDocProdDPublic/Vorgabedokumente_ZHAW/Z_RL_Richtlinie_KI_bei_Leistungsnachweisen.pdf) (section 5.2.2) requires instructors to communicate the acceptable extent of AI contribution, expectations for independent work and disclosure requirements. The [Student Information Sheet](https://gpmpublic.zhaw.ch/GPMDocProdDPublic/Vorgabedokumente_ZHAW/Z_MB_Merkblatt_Verwendung_von_generativer_KI_in_Arbeiten.pdf) explains students' corresponding responsibilities. These institutional requirements frame assessed work; the optional guide provides learning advice. Guideline version 4.0.0 and information-sheet version 2.0.0, both effective from 1 September 2026, were verified on 28 October 2026.

Prepared with AI assistance; reviewed against the linked repository examples on 26 October 2026. Detailed research and review materials for the CAS are maintained separately. The guide introduces no new assessment requirements and does not define which AI tools are permitted in assessed work.
